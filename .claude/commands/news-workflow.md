# 뉴스 수집기 기능 개발 워크플로

AI 뉴스 수집기 앱에서 새 기능을 개발할 때 사용하는 명령어입니다.
입력받은 브랜치 이름: $ARGUMENTS

아래 단계를 순서대로 실행하세요.

## 1. 현재 상태 확인
- `git status`와 `git branch --show-current`로 현재 브랜치와 작업 트리 상태를 확인한다.
- 현재 브랜치가 `main`이 아니면 경고를 주고, main으로 이동할지 사용자에게 물어본다. 사용자가 동의하기 전에는 이동하지 않는다.
- 커밋되지 않은 변경사항이 있으면 함께 알려준다.

## 2. 새 브랜치 만들기
- `$ARGUMENTS`가 있으면 그 이름으로 브랜치를 만든다(`git checkout -b <이름>`).
- `$ARGUMENTS`가 비어 있으면 어떤 기능을 개발할 것인지 사용자에게 먼저 물어보고, 답변을 바탕으로 **영어 소문자-하이픈 형식**(예: `rss-fetch`, `card-ui`) 브랜치 이름을 제안한다. 사용자가 확인하면 그 이름으로 만든다.

## 3. 개발 시작 안내
- 브랜치 생성이 끝나면 **"이제 개발을 시작하세요!"** 라고 안내한다.
- `CLAUDE.md`를 읽고 이 프로젝트의 기술 스택과 컨벤션을 다시 한번 요약해서 알려준다.
  - 기술 스택: Next.js 16 (App Router, `src/`) / React 19 / Tailwind 4, Clerk 인증, Neon + Drizzle, Claude API(`claude-sonnet-5-5`), Notion 저장, Vercel 배포
  - 컨벤션: 모든 API에서 Clerk 인증 확인 및 본인 `user_id` 데이터만 접근, API 키는 환경 변수로 관리, `proxy.ts` 사용(`middleware.ts` 아님), UI는 `ui.md` 규칙을 따르고 UI 변경 시 `ui.md`도 같은 커밋에서 갱신

## 4. 완료 처리
- 사용자가 **"완료"** 또는 **"done"** 이라고 입력하면:
  1. `git status`로 변경된 파일 목록을 보여준다.
  2. 변경 내용(`git diff`)을 바탕으로 커밋 메시지를 자동으로 제안한다.
  3. 사용자가 확인하면 커밋한다. 수정을 원하면 반영한다.
  4. 커밋 후 `main`으로 이동해 작업 브랜치를 병합한다(`git checkout main` → `git merge <브랜치>`).
- 병합 충돌이 나면 멈추고 사용자에게 상황을 알린다.

## 5. 작업 요약
- 병합이 끝나면 작업 내용을 요약해서 보여준다: 브랜치 이름, 커밋 메시지, 변경된 파일, 주요 변경 내용.
