# 커밋 전 컨벤션 검토

커밋 전에 변경된 코드가 프로젝트 컨벤션을 지키는지 검토한다.

## 참조 파일

- 검토 기준: [conventions.md](conventions.md)

## 절차

1. 현재 브랜치에서 변경된 코드를 가져온다.
   - `git status`로 변경된 파일 목록을 확인한다.
   - `git diff HEAD`로 스테이징 여부와 관계없이 변경 내용을 확인한다.
   - 추적되지 않는 새 파일(untracked)은 파일 내용을 직접 읽어 검토 대상에 포함한다.
2. [conventions.md](conventions.md)의 규칙을 기준으로 변경된 코드의 각 항목을 **통과** 또는 **개선 필요**로 표시한다.
   - 네이밍, 포매팅, 코드 품질의 모든 항목을 빠짐없이 표시한다.
   - '개선 필요'는 해당 파일과 줄 번호를 함께 적는다.
3. '개선 필요' 항목이 있으면 어떻게 수정해야 하는지 수정 전/후 코드 예시와 함께 알려준다.
4. 모든 항목이 '통과'라면 `커밋 준비가 완료되었습니다!`를 출력한다.

## 출력 형식

| 항목 | 결과 | 비고 |
|---|---|---|
| 변수·함수명 카멜 케이스 | 통과 / 개선 필요 | 파일:줄 |
| … | … | … |

'개선 필요' 항목마다 아래 형식으로 덧붙인다.

- 문제: 무엇이 규칙에 어긋나는지
- 수정 전 / 수정 후 코드 예시
